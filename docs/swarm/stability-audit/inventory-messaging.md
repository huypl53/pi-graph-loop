## Notes for scenario planning

- `swarm_send_message` is the broadest surface; a single mock-LLM scenario may need multiple turns to cover idempotency, threading, assignment auto-stamp, and TTL.
- `swarm_ack_message` and the response-credit paths are tightly coupled: the harness should verify both the message record and the task node closure path.
- `swarm_check_mailbox` is the only surface that should prove `seenAt` derivation; tmux injection alone must not count as “seen.”
- `swarm_task_message` must stay graph-neutral; the harness verdict should explicitly confirm that only `swarm_update_task` advances node status.
